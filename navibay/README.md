# NaviBay — Whole-song rhyme map

เว็บภาษาไทยวิเคราะห์เนื้อเพลงทั้งเพลงและทาย **ช่วงยอดวิวสะสม 7 ช่วง** ด้วย Multinomial Naive Bayes: <10k, 10k–99,999, 100k–499,999, 500k–999,999, 1m–4,999,999, 5m–9,999,999, >=10m ไม่ใช่การพยากรณ์ตัวเลขยอดวิวในอนาคต

## ใช้งาน

เปิด `dist/index.html` โดยตรง หรือรัน `python server.py` แล้วเปิด http://127.0.0.1:4173 ใช้เบราว์เซอร์รุ่นใหม่ที่มี Intl.Segmenter

- วางเนื้อเพลงครบทุกท่อน หรือเลือก .txt UTF-8 ได้ถึง 20,000 ตัวอักษร ไม่ตัดข้อความเงียบ ๆ
- แบ่งวรรคด้วย newline แบ่งท่อนด้วยบรรทัดว่างหรือ `[Verse]` / `[Chorus]` ป้ายท่อนไม่เป็นคำฝึก
- หากวรรคยาวเกิน 120 คำ หน้าเว็บให้แบ่งวรรคก่อน คำย่อการซ้ำ เช่น “x2” ไม่ขยายอัตโนมัติ ต้องวางท่อนที่ร้องซ้ำจริง
- คลิกพยางค์ดูคู่และตำแหน่งทั้งสองฝั่ง กรองประเภทเสียง/ตำแหน่งได้ แสดงคู่ครั้งละ 60 รายการและกดเพิ่มได้ ข้อมูลทั้งเพลงไม่ถูกตัดออกจากการทำนาย
- แสดงกลุ่มสัมผัสท้ายวรรคด้วย A/B/C ฯลฯ และรูปแบบรายท่อน เช่น AABB หรือ ABAB
- ค้นหาคู่สัมผัสที่พบบ่อยจากชุดฝึก และดาวน์โหลดผลวิเคราะห์ JSON ได้
- ข้อความที่กรอกประมวลผลในเครื่อง ไม่ส่งไปเซิร์ฟเวอร์

## สิ่งที่ตรวจ

1. สัมผัสสระ: สระ ความสั้น–ยาว และตัวสะกดตรงกัน ไม่บังคับวรรณยุกต์
2. สัมผัสอักษร: กลุ่มเสียงพยัญชนะต้นตรงกัน รวมการแยกคำควบกล้ำ
3. เสียงตัวสะกดซ้ำ: ตัวสะกดตรงกันแต่สระไม่ตรงทั้งหมด
4. เสียงสระซ้ำ: สระกับความยาวตรงกัน แต่ตัวสะกดไม่ตรง
5. สัมผัสใกล้เคียง: สระ/ตัวสะกดกลุ่มเดียวกันแต่ความยาวต่าง ไม่รวมเป็นสัมผัสสระตรง
6. คำ/พยางค์ซ้ำ: แยกจากสัมผัสสระ ไม่เพิ่มคะแนนสัมผัสตรงเพราะใช้คำเดิม
7. สัมผัสหลายพยางค์: เทียบชุดสอง/สามพยางค์ท้ายวรรค ข้อความเหมือนกันทุกพยางค์ไม่ถือเป็นสัมผัสหลายพยางค์
8. วรรคซ้ำ: ลำดับคำทั้งวรรคเหมือนกัน เป็นข้อมูลประกอบเรื่องฮุก/ท่อนซ้ำ ไม่ยืนยันว่าเป็นฮุก

ตำแหน่ง: เทียบทุกคู่ภายในวรรค; ท้ายวรรคกับทุกพยางค์ใน 3 วรรคถัดไปภายในท่อน; ท้ายวรรคกับวรรคแรกของท่อนถัดไป; และทุกคู่ท้ายวรรคที่อยู่ในกลุ่มเสียงเดียวกันตลอดทั้งเพลง คู่เดียวกันประเภทเดียวกันนับครั้งเดียว โดยเก็บตำแหน่งแรกที่ตรวจพบ ตัวกรองท้ายวรรคพิจารณาตำแหน่งจริงด้วย

## การประมาณเสียง

Intl.Segmenter ตัดคำ แล้ว dynamic programming แบ่งพยางค์ด้วยคลัง PyThaiNLP ร่วมกับพจนานุกรมเสริมและกฎเสียงภาษาไทย ครอบคลุมคำยืม (เช่น สไตล์ เบียร์ แคร์ สต็อป เทรนด์ แทร็ป ฟีล กรูฟ), อักษรนำซับซ้อน/พยางค์ลดรูป (เช่น สบาย อร่อย ถนน สวรรค์), ควบกล้ำไม่แท้ (สร้าง เศร้า ทรง), ร หัน (`รร`), การันต์ซ้อน (จันทร์ ศาสตร์), การแก้รูปพิมพ์ซ้ำ (`เเ`→`แ`, `ํา`→`ำ`) และคำภาษาถิ่นที่พบบ่อย (อีสาน/เหนือ/ใต้ เช่น บ่ ฮู้ ฮัก เด้อ คึด ซ่อย แซ่บ เปิ้น ปิ๊ก กิ๋น ใจ๋ หรอย พรือ) เก็บ offset กลับไปยังข้อความเดิม อัตราอ่านเสียงพยางค์ภาษาไทยบนชุดฝึกอยู่ที่ 98.87%

อย่างไรก็ตาม กฎชุดนี้ไม่ใช่ G2P ที่ถูกต้อง 100% ทุกคำ คำสแลงใหม่ คำหลายเสียงอ่าน และคำถิ่นเฉพาะพื้นที่นอกกฎอาจยังคลาดเคลื่อนได้ และยังไม่ประเมินเสียงร้องจริง ทำนอง การลงวรรณยุกต์กับโน้ต จังหวะดนตรี การเล่นความหมาย คำพ้อง หรือฉันทลักษณ์เฉพาะทุกชนิด

หลักการสัมผัสภาษาไทยอ้างอิง: https://academic.obec.go.th/web/images/document/1652599459_d_1.pdf

## ฝึกและทดสอบซ้ำ (Pure Python)

จากโฟลเดอร์นี้ ใช้ **Python 3.11+ (`pythainlp`, `scikit-learn`, `scipy`, `numpy`)** ทั้งหมดโดยไม่ต้องใช้ Node.js:

```bash
pip install -r requirements.txt
python train.py data/songs.csv
python test.py
python server.py
# หรือใช้ uv:
# uv run --with-requirements requirements.txt python train.py data/songs.csv
# uv run --with-requirements requirements.txt python test.py
```

CSV เป็นข้อมูลเท่านั้น ไม่ตีความเนื้อหาเป็นคำสั่ง การทำนายรุ่น v3 ประมวลผลและเทรนด้วย **Python ล้วน** (`phonetics.py` + `PyThaiNLP` + `scikit-learn`) เป็นโมเดลแบบผสมระหว่าง **Ordinal Ridge-Gaussian Regression** (`sklearn.linear_model.Ridge` ทำนาย `log10(views)` แล้วแปลงเป็นความน่าจะเป็น 7 ช่วงผ่าน `scipy.stats.norm.cdf`) และ **Complement Naive Bayes** (`sklearn.naive_bayes.ComplementNB`) บนฟีเจอร์ L2-normalized TF-IDF (คำ, word bigrams, character 3-grams, คู่สัมผัสสระ/หลายพยางค์ที่ผ่านเกณฑ์ความถี่) รวมกับฟีเจอร์เชิงโครงสร้างและเสียงระดับทั้งเพลง 40 ตัว (`StandardScaler`) พร้อมปรับ logit ตามความถี่ช่วงอย่างอ่อน (`tau=0.20`) โดยคัดเลือกไฮเปอร์พารามิเตอร์ผ่าน `GroupKFold(5)` บนชุดฝึกเท่านั้น แล้ว export เป็น `dist/model.js` เพื่อให้หน้าเว็บประมวลผลบนเบราว์เซอร์ได้โดยตรง

ลบเนื้อเพลงซ้ำโดยไม่สนช่องว่าง แล้วแบ่ง holdout ตาม artist_group (fallback artist/title) ด้วย SHA-256 byte แรก <51 เป็นชุดทดสอบ เกณฑ์ช่วงยอดวิวกำหนดล่วงหน้า ไม่ได้เลือกจากชุดทดสอบ โมเดลเผยแพร่ฝึกเฉพาะ 4,028 เพลงและทดสอบกับ 1,018 เพลง ไม่มีชื่อ ศิลปิน หรือยอดวิวเป็น features

ดู `metrics.json` สำหรับ accuracy (29.8% เทียบ baseline 28.2%), macro-F1 (0.185), within ±1 (62.4%), confusion matrix, precision/recall/F1 รายช่วง, จำนวนเพลง และ baseline เปรียบเทียบ จำนวนเพลงแต่ละช่วงไม่สมดุล (ช่วงแคบ/น้อยอย่าง `<10k`, `500k–1m`, `5m–10m` ยังมี recall ต่ำ) คะแนน probability ไม่ใช่ช่วงความเชื่อมั่นหรือโอกาสสำเร็จของเพลง
